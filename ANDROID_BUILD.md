# Building the RingWave Android APK

## What's actually in this repo right now

A complete, real, native Android project (`frontend/android/`) generated by
Capacitor, wrapping the actual RingWave web app — not a mockup. It includes:

- A working `AndroidManifest.xml` with the permissions calling actually
  needs (`RECORD_AUDIO`, `MODIFY_AUDIO_SETTINGS`, `ACCESS_NETWORK_STATE`,
  `ACCESS_WIFI_STATE`, `INTERNET`).
- A custom `MainActivity.java` that requests the microphone runtime
  permission and explicitly grants WebView `getUserMedia()` audio access
  — without this, calling would silently fail even with permissions
  granted, because Capacitor's default `MainActivity` doesn't wire this up
  on its own.
- `capacitor.config.ts` set to `androidScheme: "https"`, required for
  WebRTC and the Web Crypto call-verification feature to work at all (both
  refuse to run in a plain-HTTP context).
- The actual built web app already synced into
  `android/app/src/main/assets/public/`.

## What is NOT in this repo, and why

**There is no compiled `.apk` file.** Producing one requires the Android
SDK, Android build-tools, and Google's Maven repository
(`dl.google.com`, `maven.google.com`) to download platform/AndroidX/
Capacitor dependencies and actually compile + package + sign the app.
None of those were reachable from the sandboxed environment this project
was built in — confirmed directly (`403` on all three). This isn't a
skipped step; it's a hard constraint of that environment. Compiling the
APK has to happen somewhere with normal internet access — either your own
machine, or CI.

## Path 1: Let GitHub build it for you (no local setup)

This repo includes `.github/workflows/build-android.yml`, which does the
actual compilation on GitHub's own runners (which have full internet
access).

1. **Before running it**, set three repository secrets (Settings → Secrets
   and variables → Actions) pointing at your real, publicly-reachable
   deployed backend and AI service (see `DEPLOYMENT.md` — Railway/Render
   configs are already in this repo):
   - `VITE_API_URL` = `https://your-backend-domain/api/v1`
   - `VITE_SOCKET_URL` = `https://your-backend-domain`
   - `VITE_DETECTION_WS_URL` = `wss://your-ai-service-domain/ws/detect`

   Skipping this step produces an APK that opens but can't reach any
   backend — `localhost` (the placeholder in `.env.production`) means
   "this phone," not your server.
2. Push this repo to GitHub, or go to the **Actions** tab and manually run
   "Build Android APK" (`workflow_dispatch`).
3. When the run finishes (a few minutes), download `ringwave-debug-apk`
   from the run's **Artifacts** section. That's your installable `.apk`.

## Path 2: Build locally with Android Studio

1. Install [Android Studio](https://developer.android.com/studio) (this
   installs the SDK for you).
2. Fill in real backend URLs in `frontend/.env.production` (see the
   warning comment already in that file), then:
   ```
   cd frontend
   npm install
   npm run build
   npx cap sync android
   npx cap open android
   ```
3. In Android Studio: **Build → Build Bundle(s) / APK(s) → Build APK(s)**.
   The `.apk` lands in `android/app/build/outputs/apk/debug/`.

## Before a real Play Store release (not needed for sideloading/testing)

Both paths above produce a **debug-signed** APK — fine for installing on
a test device or sharing informally, but Google Play requires a
**release** build signed with your own permanent keystore. I deliberately
did not generate one for you: a signing keystore is a long-term identity
credential only you should hold — if I generated and embedded one in this
delivered project, you'd have no way to know it was ever secret, and
losing control of it later means losing the ability to publish updates to
this app's identity forever. To set one up:

```
keytool -genkey -v -keystore ringwave-release.keystore -alias ringwave -keyalg RSA -keysize 2048 -validity 10000
```

then follow [Capacitor's Android deployment
guide](https://capacitorjs.com/docs/android/deploying-to-google-play) to
wire it into `android/app/build.gradle` and switch the workflow/Studio
build from `assembleDebug` to `assembleRelease`.

## Known gaps, stated plainly

- **App icon/branding**: this uses Capacitor's default placeholder icon.
  Replace `android/app/src/main/res/mipmap-*/ic_launcher*.png` with real
  artwork before a public release.
- **Background call survival**: if the screen locks or the app is
  backgrounded mid-call, Android's normal power-management behavior may
  suspend the WebView's JS execution, which could drop the call. A
  production calling app typically needs a foreground service (with a
  persistent call notification) to prevent this — that's genuine native
  Android feature work beyond wrapping the existing web app, and wasn't
  built here. Flagging this rather than leaving it silently undiscovered.
- **Group call verification & detection-report naming**: both already
  documented as scoped to 1:1 calls elsewhere in this repo — same
  limitation applies here since it's the same web app.
- I could not run a real Gradle build against this project myself (same
  network constraint as above), so while I verified the Capacitor-specific
  Java APIs `MainActivity.java` relies on against Capacitor's actual
  bundled source, I could not compile it against the full Android SDK
  classpath. The first real build (via either path above) is also the
  first full compile — if something's wrong, that's where it'll surface.
